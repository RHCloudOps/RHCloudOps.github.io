Linux主机网卡（Bond）状态异常处理

一、问题定位与关键命令解析

当Linux主机的Bond网卡出现非up状态时，可通过以下命令快速定位问题：

1. 统计非up状态的从属接口数量

  • 输出示例：1
  • 说明：
    • cat /proc/net/bonding/bond*：读取所有Bond接口的配置信息。
    • grep -A 1 'Slave Interface'：匹配包含Slave Interface的行，并输出该行及下一行（-A 1）。
    • awk '/Status/{print $NF}'：提取状态字段（Status行的最后一个值，即up或down）。
    • grep -vc up：统计非up状态的数量（-v反向匹配，-c计数）。

  • 说明：直接显示每个从属接口的状态，便于快速查看具体哪些接口异常。

3. 查看详细从属接口信息

  • 输出示例：
  • 说明：
    • Slave Interface：从属网卡名称（如net4）。
    • MII Status：物理链路状态（up表示正常，down表示链路断开）。

4. 查看完整Bond接口配置

  • 输出关键字段解析：
    字段 说明
    Bonding Mode Bond模式（如802.3ad动态链路聚合、active-backup主备模式）。
    MII Status Bond接口整体状态（up表示可用）。
    Slave Interface 从属网卡名称及状态（重点关注MII Status）。
    Link Failure Count 链路故障次数（非零值表示发生过故障）。

二、故障案例分析

示例场景

从命令输出中观察到net4接口的MII Status为down，且Link Failure Count为1，说明该网卡链路已断开。

可能原因

  1. 物理连接问题：网线松动、交换机端口故障。
  2. 网卡驱动异常：驱动未加载或版本不兼容。
  3. 配置错误：Bond模式与交换机配置不匹配（如802.3ad需要交换机启用LACP）。
  4. 硬件故障：网卡或主板接口损坏。

三、故障处理步骤

1. 检查物理连接

  • 确认net4对应的网线连接正常。
  • 检查交换机端口状态，确保端口处于up状态。

2. 重启网络接口

3. 查看内核日志

4. 验证交换机配置

  • 802.3ad模式：确保交换机启用LACP并配置正确的聚合组。
  • active-backup模式：无需特殊配置，但需确保备用接口正常。

5. 更换硬件（如必要）

若确认硬件故障，更换网卡或主板接口。

四、Bond模式说明

模式 特点 适用场景
802.3ad（动态链路聚合） 多网卡负载均衡，需交换机支持LACP。 高带宽需求、冗余要求高的场景。
active-backup（主备模式） 仅主接口工作，备用接口在主接口故障时切换。 高可用性要求，对带宽需求不高。

五、关键配置文件

  • Bond接口配置：/etc/sysconfig/network-scripts/ifcfg-bondX
  • 从属接口配置：/etc/sysconfig/network-scripts/ifcfg-netX

六、总结

  • 核心命令：通过/proc/net/bonding/bond*快速定位状态异常的从属接口。
  • 处理流程：物理检查 → 重启接口 → 日志分析 → 配置验证 → 硬件更换。
  • 预防措施：定期监控Bond状态，确保交换机与主机配置一致。
